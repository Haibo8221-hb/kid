## 三、逐条明细（问题 / 模块 / 目标 / 依赖 / 负责人角色 / 验收标准）

### 3.1 P0（阻塞/紧急）

#### #16 部署 rsync 覆盖服务器活数据 ｜ CI/CD · 全版本

- **问题描述**：`deploy.yml:22-36` 的 rsync 带 `--delete`，且未排除 `data/`；本地 31 个 data 文件已入 git。任何一次 `git push` 都会用本地旧数据覆盖服务器活数据（孩子在线新增的错题/计划被静默回滚），并删除仅存在于服务器的文件（`auth_state.json` 登出水印、`llm_config.json`、`uploads/`）。
- **修复目标**：部署只同步**代码**，永不触碰**运行时数据**。
- **依赖**：无前置；但需先确认服务器 `data/` 内容完整（否则首次 exclude 后出问题无本地兜底）。
- **负责人角色**：开发（改 workflow + 验证）；家长（确认是否要把服务器数据反向拉回本地留档）。
- **验收标准**：
  1. `deploy.yml` 的 rsync 参数含 `--exclude='data/' --exclude='logs/'`；
  2. 造一次验证：在服务器 `data/` 新建一个探针文件 → 从本地 push 一次空提交 → 探针文件**仍存在**（未被删）；
  3. 服务器 `data/auth_state.json`、`data/llm_config.json` 在两次部署后仍存在。

## 四、V2 下线与迁移方案（已执行 + 留档）

### 4.1 处理总原则

> **V2 相关问题统一标注「不修复 · 随 V2 下线关闭」。** 不在 V2 上投入任何修复成本（含鉴权缺失、widget 兼容、入口保护）；仅允许从归档副本中**单向提取**配置结构。

### 4.2 下线范围

| 对象 | 内容 | 状态 |
|---|---|---|
| 代码 | `v2/` 5 文件 124 KB（diya.html、jemma.html、shared/{config,api,ui}.js） | ✅ 已移入 `backups/20261015_v2-archive/v2/` |
| 分支 / 标签 | 单分支 main，V2 无独立分支或 tag | ✅ 无需清理 |
| 镜像 / 部署 | `Dockerfile` 仅 `COPY *.html`（根目录一层），镜像从未包含 v2 | ✅ 无需处理 |
| 后端依赖 | `api_server.py` 无任何 v2 引用 | ✅ 核实无引用 |
| 服务器目录 | ECS `/www/wwwroot/kid/v2` | ✅ 随 rsync `--delete` 删除 |

### 4.3 入口与流量切换（已完成）

| 步骤 | 动作 | 时间 | 验收 |
|---|---|---|---|
| 1 | `index.html` 两处 `v2/diya.html`、`v2/jemma.html` 入口改为各自 V1 单一入口「打开工作台 →」；样式类 `card-link v2` → `primary` | 10-15 | 首页无 v2 字样 |
| 2 | 提交 + push → Actions rsync `--delete` 同步，服务器 v2 目录消失 | 10-15 | 线上首页 200 且无 v2 链接 |
| 3 | 旧书签兜底（可选，未执行）：nginx 301 `^/v2/diya\.html$ → /app.html`、`^/v2/jemma\.html$ → /jemma.html` | 按需 | 旧书签直达新页，无 404 |

### 4.4 数据迁移

- **服务端数据：无需迁移** —— V2 与 V1 共用同一套 `data/*.json`（同一后端），V2 下线不影响任何服务端数据。
- **客户端数据：随下线失效** —— 仅 V2 页面自有的 localStorage 态（主题、V2 版笔记）失效；V1 的 localStorage 键位独立，不受影响。
- **可复用资产：单向提取** —— `v2/shared/config.js` 的 children/subjects/countdowns 配置结构，在 #7（复习表统一）或 #10（前端收敛）需要时提取，**只取结构不取运行时代码**。
