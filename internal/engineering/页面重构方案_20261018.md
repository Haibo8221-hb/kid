## 3. 适龄互动清单（组件化 + 配置化）

已存在于 `assets/kid.js` 的 4 个组件直接复用（均为零依赖、幂等、localStorage 降级、找不到元素静默返回），新增 2 个小组件放同一文件内，风格对齐。

| # | 互动 | 组件 | 触发条件 | 反馈形式 | 记录数据（localStorage key） | 接入位置 |
|---|---|---|---|---|---|---|
| A1 | 今日任务打卡 | KidCheck（已有） | 点击 `.kid-task-card`（或空格/回车） | 卡片打勾 + `.kid-done-card` 降权 + `kid:change` 广播 | `kid-check-<page>-<taskId>`，值 `1`/`0` | 三周计划前 6 项卡片加 class（两页） |
| A2 | 今日进度条 | KidProgress（已有） | A1 勾选后经 `kid:change` 事件自动刷新；首次渲染在 DOMContentLoaded | "已完成 x / 6" + 填充条动画；全部完成时 `data-state="done"` 变 celebratory 态 | 无独立存储（读 A1） | `#kid-progress` 容器（已有，Diya 已接，Jemma 位置调到三周计划顶部） |
| A3 | 我的决定 | KidStamp（已有） | 点击 `.kid-decide-card` 内 `[data-choice]` 按钮 | 同卡互斥高亮 `.picked`，角标从"待你决定"变为"你的选择：xxx" | `kid-stamp-<page>-<卡片序号>` | Jemma Latin 决定卡（已有）+ Diya 决定卡（已有），仅调整位置与选项文案 |
| A4 | 反思问答 | KidAsk（已有） | 点击 `.kid-ask-q` 展开；失焦/点保存写入 | textarea + 保存/清除按钮；已存内容只读回显"你之前写的" | `kid-ask-<page>-<卡片序号>` | 两页各保留 1 张（Jemma 2 张合并为 1 张反思题） |
| A5 | **连续打卡 Streak** | **KidStreak（新增，约 60 行）** | 当天首次完成任一 A1 勾选时调用 `KidStreak.hit()`；页面加载时 `KidStreak.render('#profile-streak')` | 侧栏 `Streak N days` + 里程碑动效（3/7/30 天 toast 鼓励一次） | `kid-streak-<page>`：`{count, lastDate}` | 替换两页现有的假 streak 显示（当前显示的是 planner 填充天数 `filledDays/7`，语义错误，本次修正为真实连续打卡） |
| A6 | **点击鼓励彩蛋** | **KidCheer（新增，约 50 行）** | 点击头像/完成全部当日任务（A2 `data-state="done"`）时触发；同设备每天最多 3 次（防刷） | CSS 动画彩带（`@keyframes` + 一次性节点，300ms 后自删，无外部库） | `kid-cheer-<page>-<日期>`：当日已触发次数 | 两页头像点击 + 进度条完成态 |

**组件接入方式（配置化）**：不改 kid.js 的既有 API 约定，新增组件沿用同一模式（IIFE + `global.KidStreak` 导出）。页面接入只需在既有初始化块追加两行：

```html
<script src="/assets/kid.js?v=20261018"></script>
<script>
  window.KID_CHILD='jemma';
  KidCheck.init('body'); KidAsk.init('body'); KidStamp.init('body');
  KidProgress.render('#kid-progress');
  KidStreak.render('#profile-streak');      // 新增
  KidCheer.init('#profile-avatar');         // 新增
</script>
```

新增 kid.js 预计 +8KB（未压缩源码，gzip 后 <3KB），对首屏无感知影响（两页 script 均在 `</body>` 前同步加载，模式不变）。

## 4. 流水线集成：需要改动的位置

| # | 文件 | 改动 | 原因 |
|---|---|---|---|
| P1 | `.github/workflows/deploy.yml` | test job 增加一步 `Setup Node` + `node tools/smoke_test.cjs`（jsdom 需从 workspace 取，CI 里改为 `npm i jsdom --no-save` 或 `npx jsdom`）；给 smoke_test.cjs 的 `JSDOM_PATH` 加 CI 分支解析 | 本次重构动的是 HTML 结构与 onclick 引用，smoke 的"悬空 onclick 检查"正是防回归的关键，必须进 CI |
| P2 | `tools/smoke_test.cjs` | `APP_HTML` 之外追加 `JEMMA_HTML` 双页回归；REQUIRED_FNS 按新结构补充（新增组件不引入新全局函数则只加页面断言） | 现在只冒烟 app.html，jemma.html 无自动化保护 |
| P3 | `tests/check_links.py` | 无需改逻辑；重构后新入口若指向仓库内文件必须真实存在（`downloads/`、`resources/` 已在 SERVER_ONLY_DIRS 跳过名单） | 附件入口只折叠不删文件，链接不会失效；但新增锚点/链接需过此关 |
| P4 | 两个 HTML 的 `<script src="/assets/kid.js">` | `?v=` 从 `20261015`/无版本 bump 到 `20261018`（kid-common.js 同步） | 沿用仓库既有缓存刷新约定，保证 ECS 上 nginx 静态缓存不返回旧组件 |
| P5 | rsync exclude 列表 | **不动**。`assets/` 不在 exclude 中，新组件文件自然随部署上线 | 确认即可，无改动 |

**性能保障**：无打包器即无 bundle 劣化风险；kid.js 零依赖零网络请求；新增动画纯 CSS；`<details>` 折叠减少首屏渲染节点数（jemma 首屏约减 40% DOM）。加载性能不劣于现状。

**安全红线（不动）**：登录守卫（401 → login.html）、`/api/*`、nginx-git-protect、data/logs 的服务器唯一真源约定、deploy key 不进 webroot——本重构只碰 HTML/assets，与上述全部无交集。
