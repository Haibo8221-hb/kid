## A 类 · 去重清单（8 项）

### A1 重复功能模块：三周计划在两处渲染
- **位置**：Dashboard `#twp-diya`（L580、L3405）与 Route Compare `#twp-diya-route`（L820、L3406），同源 `THREE_WEEK_PLAN`（L3365）。
- **问题**：同一模块在两个 tab 各渲染一份，内容完全一致；未来改计划要改两处、漏一处就出现两 tab 说法不一。
- **改法**：保留 Dashboard 的完整渲染；Route Compare 处（L816-824）改为一行文字链接「📌 本周三周计划见 Dashboard →」（点击 `switchTab('dashboard')`）。区块删除但内容零丢失（Dashboard 仍在）。
- **原因**：重复功能模块是维护性缺陷；Route Compare 的主题是升学路线对比，嵌一份执行计划本就文不对题。
- **影响范围**：仅 Route Compare tab 首屏。
- **风险**：低。

### A2 重复表述：Strengths / Watch List / Risk Heatmap 三区块互相重复（且口径不一）
- **位置**：L627-634（Strengths）、L639-644（Watch List）、L650-672（Risk Heatmap + Core Assessment）。
- **问题**：
  - Maths 75% / Physics 71% / English improving / Drama 同时在 Strengths 和 Heatmap「LOW/CONFIRMED」卡出现；
  - 化学 44%、English analysis depth、History 16-marker 同时在 Watch List 和 Heatmap「HIGH/MEDIUM」卡出现；
  - **口径过期**：Watch List 写「化学 44%」（7 月 mock 口径），而 L2204 学科卡已是「Oct26 · 6，7月mock 44% → 明显回升」——同一区块上方下方数据不一致。
- **改法**：Heatmap 三张卡片改为**只保留 Strengths/Watch List 中没有的判断维度**（概率×Impact 矩阵本身是独有信息），重复的科目文字从卡片中移除；Core Assessment 段保留。Watch List「化学 44%」同步更新为学科卡的最新口径「Oct26 等级 6，冲 7 还差一级」。
- **原因**：同一事实三处陈述，必然漂移（现在已经漂移了）；去重的同时顺带修正数据不一致。
- **影响范围**：Dashboard 一个 section 内部，无结构变化。
- **风险**：低（纯文案层面）。

### A3 死代码：Wiki 整模块 + Activity Feed + Dashboard 两个孤儿分支
- **位置**：`#wiki-modal` DOM（L926-947）；`loadWikiEntries/openWikiModal/closeWikiModal/saveWikiEntry/deleteWikiEntry/switchWikiChild`（L2543-2606）；`loadActivityFeed`（L2929-2945）；`loadDashboard` 中 `diya-wiki-summary` / `diya-chat-summary` 分支（L1971-1988）。
- **问题**：grep 验证——`openWikiModal` 无任何调用者；`#wiki-entries`、`#activity-feed`、`#diya-wiki-summary`、`#diya-chat-summary` 四个容器在 DOM 中均不存在。整个 Wiki 功能对孩子不可见、不可达，约 160 行代码 + 1 个 modal 永不被执行。
- **改法**：整块删除（后端 `/api/wiki` 不动，数据不丢）。
- **原因**：死功能模块——留着只会造成「以为有 journal 功能」的误判和后续维护成本。
- **影响范围**：无任何 UI 变化（本就不可见）；JS 体积约 -6KB。
- **风险**：低（单文件应用，无外部引用；删除前再跑一次 grep 确认）。

### A4 死代码：loadChild / drawChildRadar / switchChatChild
- **位置**：L2299-2317。
- **问题**：`drawChildRadar` 渲染到 `diya-radar` / `diya-radar-legend`，两个元素不存在；`switchChatChild` 无任何 UI 触发（chat 头部只有静态「Chat with Diya」）；`loadChild` 只被 A4 自身链路引用。
- **改法**：三个函数整体删除；`currentChatChild` 变量保留（`sendChatMsg` L2384/L2410 在用）。
- **原因**：双雷达图/双孩聊天是从 jemma 结构复制过来的残留，Diya 页面没有对应 UI。
- **影响范围**：无 UI 变化。
- **风险**：低。

### A5 死代码 + 显示异常：Streak 永远显示 0 days
- **位置**：`loadStreak`（L2165，DOMContentLoaded L3407 有调用）、`startStreak`（L2188，**零调用**）。
- **问题**：`loadStreak` 只做「重置/保持」，`startStreak`（唯一写 count=1 的函数）从未被调用 → 侧栏 `Streak 0 days` 是永久的假数据，属于显示异常。
- **改法**：删除 `startStreak`；在 `toggleTask`（L1469，勾选/取消任务）成功后调用 `loadStreak(true)`——给 `loadStreak` 加一个可选参数 `bump`：勾选时若 `lastDate!==today` 则 `count+1, lastDate=today`。这样侧栏显示的是**真实连续打卡天数**，且不新增任何 UI。
- **原因**：修复「显示与数据脱节」；改动最小（一个函数加 4 行）。
- **影响范围**：侧栏 profile-streak 文案与颜色（L2181-2182 已有分级配色逻辑，修复后自然生效）。
- **风险**：低。

### A6 死代码：旧 renderTasks（47 行近似重复实现）
- **位置**：`renderTasks`（L1411-1457）与 `renderTasksEnhanced`（L3050-3111）；L3128 `renderTasks = renderTasksEnhanced;` 别名替换。
- **问题**：两份近似实现，旧的那份已被别名顶掉，永不被执行（`loadTasks` 在 kid-common 里调 `renderTasks`，实际跑到 enhanced）。
- **改法**：删除旧 `renderTasks`（L1411-1457），把 `renderTasksEnhanced` 更名为 `renderTasks`，删掉 L3128 别名行。
- **原因**：重复功能模块去重；别名模式脆弱（依赖执行顺序）。
- **影响范围**：无行为变化（别名本就指向 enhanced）；任务列表渲染逻辑不动。
- **风险**：低（smoke 测试有 `renderTasksEnhanced` 断言——见 S 阶段说明，需同步更新测试引用）。

### A7 重复配置源：两套倒计时定义，实际渲染只用一套
- **位置**：`TIMER_TARGETS`（L1400-1404，含 Half Term 2026-10-26）与 `COUNTDOWN_ITEMS`（L2609-2612，含 GCSE + Sixth Form）。`renderCountdownStrip` 只读后者。

- **原因**：单一配置源；顺带找回丢失的倒计时项（信息增量来自既有配置，不是新增内容）。
- **影响范围**：首页倒计时条从 2 项变 3 项。
- **风险**：低。

## B 类 · 修 bug 清单（8 项）

### B1 交互失效：Subject Analysis 整个 tab 不可达
- **位置**：`#tab-subject-analysis` DOM（L1000）；侧栏 nav（L513-521）**没有** subject-analysis 入口；`switchTab` 没有对应 case；`loadSubjectAnalysis`（L2900）零调用。
- **问题**：这个 tab 在任何路径下都打不开——没有导航项、没有调用者；即使打开也会永远停在「Loading...」。是彻底的死 tab + 死函数。
- **改法**：侧栏加一项「📊 Subject Analysis」（放在 Error Book 后面），`switchTab` 加 `if(tab==='subject-analysis') loadSubjectAnalysis();`。
- **原因**：交互失效的标准案例；修复是「恢复既有功能的入口」，不是新功能。
- **影响范围**：侧栏 +1 项；该 tab 从不可用变为可用（内容本就是完整的学科错题统计）。
- **风险**：低。注意：`loadSubjectAnalysis` 拉全量 errors（未分页），与 B2 的 #12 分页改造精神不符——修复时顺手加 `?limit=200` 上限或改为调 `?stats=1` 口径，二选一，实施时定。

### B2 交互失效：deleteError 在 question 为对象时静默崩溃
- **位置**：L2888-2891。
- **问题**：label 计算在 `try` 之外：`(error.question||'').slice(0,50)`——`renderErrors`（L2824）自己都处理了 `question` 可能是对象的情况（上传 OCR 入库的错题就是对象），此处 `.slice` 会抛 `TypeError`，confirm 都弹不出来，删除按钮对这类错题完全失效。
- **改法**：label 计算改用与 L2824 同款的兼容取值，并挪进 `try` 内（或先算值再 confirm）。
- **原因**：交互失效 + 异常位置错误。
- **影响范围**：错题删除功能（对象型 question 的错题）。
- **风险**：低。

### B3 逻辑错误：markdownToHtml 的引用转换永不生效
- **位置**：L2341 `html=html.replace(/^&gt; (.+)$/gm,'<blockquote>$1</blockquote>');`。
- **问题**：正则匹配的是 HTML 实体 `&gt;`，而 markdown 原文里是 `>` 字符——这个替换永远不命中，AI 回复里的引用全部丢失样式。
- **改法**：改为 `/^&gt;\s*|^>\s?/` 一次性兼容两种输入（或先转义再匹配 `&gt;`，见 B4）。
- **原因**：逻辑错误。
- **影响范围**：AI 聊天气泡渲染。
- **风险**：低。

### B4 安全/逻辑：markdownToHtml 不转义，聊天气泡可直接注入 HTML
- **位置**：L2318-2352（`markdownToHtml`）+ L2361/L2402（`bubble.innerHTML=markdownToHtml(...)`）。
- **问题**：用户输入与 AI 回复未做 `&<>` 转义就直接进 `innerHTML`；markdown 链接 `[](...)` 也不校验协议，`javascript:` URL 可构造。虽然内容源主要是自己的 LLM，但孩子粘贴的任何文本都会进这个管道。
- **改法**：入口先 `escHtml(md)` 再跑后续 markdown 替换（替换产生的 `<strong>/<code>` 等标签在转义后插入，不受影响）；链接正则加协议白名单（http/https/mailto 外一律降级为纯文本）。
- **原因**：逻辑缺陷（XSS 面）。
- **影响范围**：聊天渲染；**需回归**代码块/加粗/斜杠转义场景。
- **风险**：中——列为 P1，实施时重点手工验证。

### B5 逻辑错误：SMC 表单读取不存在的 smc-notes 字段
- **位置**：L2143 `notes: val('smc-notes') || ''`；表单 DOM（L683-697）没有该输入。
- **问题**：`notes` 永远是空串——死字段读取。
- **改法**：删除该行（后端 notes 字段保留，不影响）。
- **原因**：逻辑错误（死代码）。
- **影响范围**：SMC 记录保存 payload。
- **风险**：无。

### B6 显示异常：Planner 周切换按钮是空的
- **位置**：L855/L857 `<button class="btn-sm" onclick="changeWeek('diya',-1)"></button>`。
- **问题**：两个按钮无任何文字/图标（`.btn-sm` 无 `::before` 内容），渲染成两个小空块，孩子不知道能切换周。
- **改法**：补 `‹` `›` 文字 + `title="上一周/下一周"`。
- **原因**：显示异常。
- **影响范围**：Weekly Plan tab 控件。
- **风险**：无。

### B7 代码卫生：注释与行为不符 + 空三元
- **位置**：L1320-1322（`switchNotesTab` 注释称「仅选中科目时显示添加按钮」，实际永远显示）；L1446 `${item.done?'':''}` 空三元（随 A6 删除）。
- **改法**：修正注释使其描述实际行为；空三元随 A6 一并消失。
- **原因**：误导后续维护者。
- **影响范围**：无运行时变化。
- **风险**：无。

### B8 缓存风险：kid.js 缺版本戳，修复可能被缓存吃掉
- **位置**：L3427 `<script src="/assets/kid.js"></script>`（对比 L1139 `kid-common.js?v=20261015` 有戳）。
- **问题**：kid.js 无 `?v=`——历史上已发生过「缓存旧版 app.html 导致 LLM 按钮失效」事故（L1180 注释自证），同类风险仍在。
- **改法**：改为 `/assets/kid.js?v=20261018`（kid-common 同步 bump）。
- **原因**：防止修复上线后用户端不生效。
- **影响范围**：无功能变化。
- **风险**：无。
